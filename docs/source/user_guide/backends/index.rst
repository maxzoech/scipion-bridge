Backends
========

.. currentmodule:: scipion_bridge

Protocols, shell commands and proxies never talk to the operating system or
to an execution engine directly. They ask for *services*, and a backend
supplies them through dependency injection (the ``dependency-injector``
package). The same protocol code therefore runs unchanged in a notebook, on a
Ray cluster, and inside Scipion. This section describes the services and each
of the three backends that ship with the library.

.. contents:: On this page
   :local:
   :depth: 2

Services
--------

Each backend is a container that provides these services:

.. list-table::
   :header-rows: 1
   :widths: 28 72

   * - Service
     - Responsibility
   * - ``shell_exec``
     - Runs the commands generated by ``@shell_command``.
   * - ``temp_file_provider``
     - Creates and deletes the temporary files of proxies.
   * - ``storage_provider``
     - Creates array groups (in memory, or Zarr in a Scipion protocol). The
       array types keep their data in memory and do not use it; see
       :doc:`/developer/struct_storage`.
   * - ``protocol_config_provider``
     - Serves parameter values to ``Field.value``.
   * - ``resource_provider``
     - Builds and caches ``Resource`` values.
   * - ``streaming_backend``
     - Compiles streaming graphs into runnable pipelines.

Library code declares the services it needs; a container is *wired* into the
library's modules, which replaces those declarations with the container's
services. Replacing a single service, for example the command executor in a
test, is a matter of overriding one provider of the container.

Choosing a backend
------------------

.. list-table::
   :header-rows: 1
   :widths: 18 40 42

   * - Backend
     - Use it for
     - Configured by
   * - Standalone
     - Scripts, notebooks, tests
     - ``scipion_bridge.backend.configure_default_env()``
   * - Ray
     - Running protocols in parallel and distributed
     - ``RayPipelineRunner``, which configures itself
   * - PyWorkflow
     - Running protocols inside Scipion 3
     - ``convert_protocol_to_scipion3_protocol``

The backends differ in the implementation of each service:

.. list-table::
   :header-rows: 1
   :widths: 25 25 25 25

   * - Service
     - Standalone
     - Ray
     - PyWorkflow
   * - ``shell_exec``
     - ``subprocess``
     - ``subprocess``, in the worker
     - the protocol's ``runJob``
   * - ``temp_file_provider``
     - system temp dir
     - system temp dir of the worker
     - the protocol's ``tmp`` dir
   * - ``protocol_config_provider``
     - none (provide one in tests)
     - values given to the runner
     - values of the Scipion form
   * - ``resource_provider``
     - per process
     - per process, or per cluster
     - per process
   * - ``streaming_backend``
     - Ray, if installed
     - Ray
     - Ray, if installed
